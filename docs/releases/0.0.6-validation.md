# OhmLauncher 0.0.6 validation

Release candidate: `0.0.6`, version code `12`, package
`cl.villagranquiroz.ohm_launcher`. Validation completed on 2026-10-02.

## Automated checks

- Clean Kotlin compilation of `debug`, `release`, `playRelease` and debug tests.
- 782 JVM tests in 126 suites: zero failures, errors or skipped tests.
- Four tests exchange real mutual-TLS sessions with Go LAN providers, covering
  native Flux and legacy identities in both connection directions. Helpers are
  compiled separately against each desktop baseline; private identities are
  generated temporarily and are not checked in.
- Full Android lint for both release editions: zero errors, 149 warnings each.
- Signed full APK, signed Play APK and signed Play AAB built from the same checked
  sources. Duplicate vital-lint tasks were excluded only after full lint passed.
- AAB validated with bundletool 1.18.3 and its JAR signature verified. A universal
  Play APK was generated from that exact bundle using the existing upload key.
- APK signatures verified. Upload certificate SHA-256:
  `5ca383d6cf8eb6458c4727274773af3ed59ff7cb33bcf5a3dd4b3a927b774140`.
- Both APKs pass 16 KB ZIP alignment. All packaged `arm64-v8a` and `x86_64`
  libraries have at least 16 KB ELF LOAD alignment. The AAB declares
  `PAGE_ALIGNMENT_16K`.

## Play artifact boundary

The bundle manifest identifies version `0.0.6` / `12`, target SDK 36 and minimum
SDK 24. Backup is disabled. Optional Omarchy Link uses authenticated local HTTP;
its transport is unencrypted, and cleartext traffic is enabled accordingly.

The Play artifact declares only the minimal `OmarchyNavigationService` and
`TtfxWallpaperService`. It has no notification listener, clipboard service,
screen-capture service, broad storage permission or full remote-control
accessibility service. Shared classes can remain in bytecode; distribution gates
keep Flux, file transfer, text sharing, mirroring and remote input unavailable.

All 19 localized store listings and release-note blocks were checked against
their character limits and the Play feature boundary.

## Functional scope and limits

Theme and original-background synchronization, the theme-style Background
carousel with its final Custom card, pairing approval and temporary desktop input
were physically verified with the previously installed legacy desktop baseline.
Those checks are distinct from the automated native-Flux interoperability checks
for this release. The upstream desktop candidate was not deployed over the
working desktop during release preparation.

A clean Play runtime smoke test is tracked separately from the successful build,
manifest, signature and automated checks. An AAB on disk does not imply a Play
Console upload, review submission or rollout; each store step must be verified
in the live console.
